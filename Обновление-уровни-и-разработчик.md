# Темы, уровни и кабинет разработчика

Главный экран → **Уровни** → одна из 7 тематических групп → один из 5 уровней. Все 35 уровней доступны для выбора. В каждом 10 независимых задач; параметры перемешаны отдельно для каждого вопроса и попытки. Три ошибки завершают только текущую попытку. Лучшие результаты сохраняются, повторное прохождение не позволяет бесконечно набирать очки. Диплом выдаётся после прохождения всех 35 разных уровней.

Кабинет находится по адресу `/developer.html`; ссылка есть внизу игры. Он содержит список игроков, поиск, текущие блокировки, последние 200 событий отсутствия и последние 100 решений. Обновляется каждые 15 секунд. Блокировка требует причины и срока: от 20 до 1440 минут (в том числе произвольный срок) либо навсегда. Можно снять блокировку. Сервер проверяет её при запросах игры, подсказок и диплома; временная блокировка перестаёт действовать автоматически.

## Подключение к рабочему сайту

Обновление опубликовано 10 ноября 2026 года: [игра](https://mathquest-expedition.vercel.app), [кабинет разработчика](https://mathquest-expedition.vercel.app/developer.html). Neon подключён, миграции выполнены, аккаунт разработчика создан с указанным вами паролем. Ниже — справочные шаги для повторного развёртывания; сейчас выполнять их не нужно.

1. Установите Node.js 24+ и выполните `npm ci` в папке проекта.
2. В серверном файле `.env.local` задайте `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` из вашей конфигурации. Для создания аккаунта добавьте `DEVELOPER_INITIAL_PASSWORD` со значением пароля, который вы указали в задании. Пароль намеренно не хранится в исходниках, HTML или JavaScript браузера.
3. Выполните `npm run migrate`, затем `npm run setup:developer`. Будет создан аккаунт `asadbek1981uz@gmail.com` с серверной ролью разработчика и хешем заданного пароля. Обычная регистрация этого адреса запрещена. Если адрес уже занят аккаунтом без роли, команда остановится: сначала необходимо проверить владельца записи в базе. Повторный запуск не сбрасывает пароль существующего разработчика.
4. Удалите `DEVELOPER_INITIAL_PASSWORD` из окружения после успешного создания аккаунта. Файл `.env.local` исключён из Git.
5. Разверните проект на Vercel с серверными переменными окружения. Команда сборки уже выполняет миграции. Для местного запуска можно использовать `npx vercel dev` с соответствующим `BETTER_AUTH_URL`.
6. Откройте `/developer.html` и войдите указанным аккаунтом. Обычные игроки не имеют доступа к данным кабинета, даже если откроют этот адрес напрямую.

## Как работает контроль отсутствия

Во время открытого игрового экрана события `blur` и `visibilitychange` отправляют начало отсутствия. Время хранится в PostgreSQL. Через 120 секунд игра показывает предупреждение; кабинет видит статус предупреждения. Через 180 секунд событие отмечается «На проверку». Разработчик выбирает наказание вручную. При возврате событие закрывается, история остаётся. Повторное открытие страницы завершает оставшееся открытым событие.

Браузер не может показать поверх чужой вкладки предупреждение сайта. Если вкладка заморожена, сообщение отобразится при возобновлении работы. Кабинет рассчитывает длительность на сервере и поэтому видит открытые события даже при остановленных таймерах игрока. Закрытие страницы и потеря сети тоже могут оставить открытое событие; они отмечены как «возврат не зафиксирован». Если начало отсутствия не дошло до сервера из-за отсутствия сети, точную длительность восстановить нельзя.

Это мониторинг для ручной проверки, а не доказательство использования читов. Модифицированный браузер может скрыть события фокуса. Сервер отдельно проверяет ответы, версию прогресса, права разработчика и блокировки. Ответы не принимаются от клиента как готовые оценки.

## Проверка

`npm test` проверяет математические задания, произвольный порядок прохождения, защиту от повторного начисления очков, завершение попыток, пороги отсутствия и допустимые сроки блокировки. Полная проверка входа, миграций и обмена между устройствами требует настроенной PostgreSQL и серверного окружения.
